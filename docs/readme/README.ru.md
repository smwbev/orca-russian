## Установка

### Способ 1 — через маркетплейс (рекомендуется)

Установку через маркетплейс можно обновлять на месте: кнопка **Check for update** на карточке пакета подтягивает свежий выпуск.

До включения пакета интерфейс английский, поэтому названия кнопок и разделов ниже даны так, как они выглядят на экране.

1. **Settings** → **Plugins** → включите **Plugin system**.
2. Нажмите **Manage sources**. Вставьте адрес в поле **Git URL**, в поле **Git ref** оставьте `main` и нажмите **Add source**:

   ```
   https://github.com/smwbev/orca-plugins.git
   ```

3. На вкладке **All** найдите карточку **Russian** от `smwbev`, нажмите **Install** и подтвердите кнопкой **Install plugin**.
4. Orca откроет окно **Review plugin**. Пакет — декларативное содержимое без кода плагина; нажмите **Enable plugin**. Пока этого не сделать, язык в списке не появится.
5. **Settings** → **Appearance** → **Language** → выберите `ru-RU — smwbev.russian`.

> Начиная с Orca v1.4.169 обвязка раздела плагинов переводится — это результат [нашего PR #12455](https://github.com/stablyai/orca/pull/12455). Тексты согласия и доверия остаются английскими намеренно: их движок запрещает переопределять. Подробнее — [ниже](#почему-часть-строк-остаётся-английской).

### Способ 2 — напрямую по Git URL

Если маркетплейс не нужен, поставьте пакет одной ссылкой.

1. **Settings** → **Plugins** → **Install plugin** → вкладка **Git URL**.
2. Вставьте адрес репозитория **вместе с явным `#ref`** — без него Orca откажет в установке, чтобы каждая установка была привязана к конкретной версии:

   ```
   https://github.com/smwbev/orca-russian.git#v5.1.176
   ```

   После `#` подойдёт любой тег или коммит. Отдельного поля для ref в этом окне нет — он указывается прямо в адресе.

3. В окне **Review plugin** нажмите **Enable plugin**.
4. **Settings** → **Appearance** → **Language** → `ru-RU — smwbev.russian`.

### Способ 3 — локальная папка для разработки

Подходит, если вы правите перевод у себя.

1. Клонируйте репозиторий в постоянную папку:

   ```bash
   git clone https://github.com/smwbev/orca-russian.git
   ```

2. **Settings** → **Plugins** → **Development** → введите полный путь к папке и нажмите **Add path**.
3. Когда Orca попросит, просмотрите и включите плагин, затем выберите язык. Если пакет не появился, перезапустите Orca.

### Почему часть строк остаётся английской

313 ключей каталога Orca v1.4.242 остаются английскими, и ни один из них не пробел в работе:

- **180 строк** — тексты согласия и доверия в плагинах. Движок защищает пространство имён `auto.components.settings.plugin*` (проверка регистронезависимая), чтобы плагин не мог переписать диалог согласия, бейдж происхождения, статус безопасности или подтверждение необратимого действия. Если языковой пакет переопределит хотя бы один такой ключ, Orca отклонит **весь пакет целиком**, и русский язык просто не загрузится.
- **122 ключа** — осиротели: 112 остались после отката и повторного выпуска обмена навыками, ещё 10 — от настроек SSH-маршрутизации браузера и автоматизаций, переписанных на месте. Их не читает ни один компонент, перевод только утяжелил бы пакет.
- **11 строк** — по-русски выглядят так же (`SHA-256`, `· SSH`, `WSL ·`, образец ссылки, `{{name}} +{{count}}`) либо разбиты на фрагменты, к которым компонент сам приклеивает английское окончание `s`.

Список сокращается по мере того, как Orca принимает наши правки:

- **34 строки** ушли из него в [PR #11826](https://github.com/stablyai/orca/pull/11826) — статусные подписи в настройках и статистике собирались из литералов в коде и не доходили до каталога вовсе. Переведены начиная с v5.1.0.
- **ещё 34** ушли в [PR #12455](https://github.com/stablyai/orca/pull/12455), который сузил правило защиты: заголовки разделов, пустые состояния, «Обновить» и форма локальной разработки не несут решения о доверии и стали переводимыми. Вошло в Orca v1.4.169, переведено начиная с версии пакета 5.1.7. Более старая сборка Orca отклоняет каталог с этими ключами, поэтому манифест объявляет `engines.orca >=1.4.169`: такая сборка откажет в установке и назовёт нужную версию.

Все остальные строки, отсутствующие в пакете, Orca показывает по-английски автоматически — это штатный механизм отката, приложение при этом работает нормально.

## Обновление

**Через маркетплейс:** в разделе **Настройки** → **Плагины** нажмите **Check for update** на карточке пакета, затем **Update plugin**. Эти две кнопки движок переводить не разрешает, поэтому они остаются английскими.

**По Git URL:** переустановите плагин, указав новый тег.

История версий: [releases](https://github.com/smwbev/orca-russian/releases) начиная с v5.1.157, всё более раннее — в [тегах](https://github.com/smwbev/orca-russian/tags). Версии выходят по схеме `vX.Y.Z`, где смена мажорной означает завершение крупного этапа перевода.

## Как устроен пакет

```
orca-plugin.json        манифест: идентификатор, версия, ссылка на каталог
locales/ru-RU.json      каталог переводов, 16 874 строки и 217 добавочных форм множественного числа
GLOSSARY.md             глоссарий: правила и единая терминология
tools/                  сборка, проверка выпуска и аудит пакета — см. tools/README.md
```

Orca подключает языковой пакет под синтетическим кодом языка, поэтому в списке языков он отображается как `ru-RU — smwbev.russian`. Ключи каталога совпадают с ключами английского оригинала `src/renderer/src/i18n/locales/en.json`; всё, чего нет в русском файле, берётся из английского.

Русскому нужно больше форм множественного числа, чем есть в английском. Сегодня Orca выбирает форму в пакете по двум английским ([stablyai/orca#12106](https://github.com/stablyai/orca/issues/12106)), поэтому строка, которая достаётся всем числам, кроме единицы, сформулирована так, чтобы читаться при любом числе: «сохранено веток: 5».

217 добавочных записей — это формы, которых в английском нет: `_few` и `_many` для 20 семейств множественного числа и `_one`, `_few` и `_many` для 59 строк, которые Orca вызывает со счётчиком, но хранит одним текстом. Сегодня показываются только формы `_one` — там, где у строки нет отдельного ключа для единицы: «1 агент» вместо «Агентов: 1». Остальные начнут показываться в тот день, когда смержат [stablyai/orca#12505](https://github.com/stablyai/orca/pull/12505).

Каждый выпуск пересобирается скриптом [`tools/build.py`](../../tools/build.py) и проверяется по правилам последнего релиза Orca, а не ветки `main`:

| Ограничение | Лимит | Сейчас |
|---|---|---|
| Узлов в каталоге | 20 000 | 19 187 |
| Глубина вложенности | 16 | 12 |
| Длина строки | 8 192 символа | в пределах |
| Размер файла | 5 МБ | ~1,5 МБ |

[`tools/audit-pack.py`](../../tools/audit-pack.py) прогоняет те же проверки на любом языковом пакете, не только на этом: примет ли движок каталог, что релиз оставил без перевода и каких ключей в нём больше нет.

## Терминология

Перевод следует единому глоссарию — [GLOSSARY.md](../../GLOSSARY.md). Он фиксирует не только соответствия терминов, но и правила: безличные формы обращения, дословный перенос плейсхолдеров, последовательное написание «ё», типографские кавычки и многоточия, различение похожих понятий.

Несколько опорных решений:

| Английский | Русский | Почему |
|---|---|---|
| workspace | рабочая область | ключевой термин, встречается во всех разделах |
| worktree | рабочее дерево | отдельная сущность, с workspace не смешивается |
| pull request | пул-реквест | устоявшаяся форма; аббревиатура PR не переводится |
| merge request | мерж-реквест | GitLab; MR остаётся латиницей |
| review | ревью | не путать с checks — «проверки» |
| skill | навык | «скилл» не используется |
| session | сессия | «сеанс» не используется |

Команды git, названия продуктов и внутренние идентификаторы намеренно остаются латиницей.

1. Что написано сейчас и как, на ваш взгляд, должно быть.

## Совместимость

Требуется **Orca 1.4.169 или новее**. Подключаемые языковые пакеты появились в 1.4.160, но этот пакет переводит 34 строки настроек плагинов, которые движок разрешает переопределять только начиная с 1.4.169, а более старая сборка отклоняет весь каталог из-за одной такой строки. Манифест объявляет минимальную версию, поэтому старая Orca откажет в установке и назовёт нужную версию, а не останется молча на английском.

**Исправлено в Orca 1.4.229: падение дорожной карты.** В Orca 1.4.198 – 1.4.227 при включённом языковом пакете открытие дорожной карты GitHub Project роняло страницу «Задачи»: дорожная карта передавала форматировщику дат внутреннее имя ресурса пакета, и тот его отвергал. Исправление ([#26860](https://github.com/stablyai/orca/pull/26860)) вошло в Orca 1.4.229; до этого оно было только в отозванных 1.4.225 и 1.4.226, а в хотфиксе 1.4.227 его не было. Если у вас более ранняя версия, обновите Orca.

Пакет содержит только текстовые данные: он не выполняет код, не запрашивает разрешений и не имеет доступа к вашим файлам, репозиториям или учётным данным. Скрипты в `tools/` обслуживают каталог; точки входа манифест не объявляет, поэтому Orca их никогда не запускает.
